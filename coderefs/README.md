# Code and API references of the reports, aligned to DraCor API 1.5

Machine-readable record of every reference from the report editions (`book/clsinfra-d7N/*.md`)
into DraCor code and API endpoints, with its counterpart in the upcoming release line.
The book itself is **not** changed. This table is meant to drive later editorial notes or
repointed links (1.x) and a drift check (#23).

Generated by `tools/coderefs.py`, which needs clones of dracor-api, dracor-frontend,
dracor-metrics and dracor-react with tags. Put them in `.cache/repos/` (git-ignored) or set
`CODEREFS_REPOS`:

    .venv/bin/python tools/coderefs.py

Targets, as of 2026-11-20 (set in `TARGET` at the top of the script):

| repo | target | note |
|---|---|---|
| dracor-api | 1.5.0-rc.1 | each unit is also compared with `main` (c110a27, 2026-11-17), see `main_differs` |
| dracor-frontend | 3.0.0-rc.1 | TypeScript rewrite; components are also searched in dracor-react 1.11.0 |
| dracor-metrics | 1.6.0 | |

## Files

### `code-links.csv`: one row per occurrence of a GitHub link into dracor-api, dracor-frontend or dracor-metrics

| column | meaning |
|---|---|
| `report`, `page`, `section`, `paragraph`, `footnote` | where the link occurs. For a footnote, `paragraph` is the paragraph that references it. |
| `link_text`, `url` | the link as printed (e.g. `<56>`) and its target |
| `repo`, `ref`, `pinned`, `resolved_ref` | `ref` is a commit, or a branch for unpinned links. Branch links (`blob/main/…`) are resolved to the branch state at the report's publication date (`resolved_ref`). |
| `path`, `line_from`, `line_to` | the referenced file and lines |
| `kind` | `unit` (lines inside a function or component), `file`, `lines (no unit)` (module prolog, variables, types), `unpinned (branch)`, `branch ref (gone)` |
| `unit`, `signature_report` | the function or component at the referenced lines. XQuery signatures are normalised as in the DraCor OKG (`name(type, …)`). |
| `target_release` | the repo and tag where the counterpart was found (for the front end it can be `dracor-react@1.11.0`) |
| `status` | `unchanged`, `changed`, `gone`, `file exists`, `file moved/renamed`, `file removed`, `unresolvable` |
| `match` | how the counterpart was found: `same name`, `same name, other signature`, `renamed? (body similarity)` (best match ≥ 0.5 among all units; check it), `line window`, `same path`, `same file stem` |
| `similarity` | 0–1, token similarity of the code (comments and layout ignored, so the prettier reformatting in 1.5.0-beta.1 does not count) |
| `target_unit` | new name or signature, if it differs |
| `target_url` | permalink to the counterpart at the target tag |
| `changed_in_releases`, `change_commits` | releases and commits that changed the unit between the report commit and the target (`git log -L`). Pure formatting commits are listed but not counted as releases. |
| `main_differs` | dracor-api only: `yes` if the unit on main differs from 1.5.0-rc.1, or `unit gone on main` |
| `action` | suggestion: `keep`, `repoint (same code)`, `repoint`, `repoint, check text` (similarity ≥ 0.6), `repoint + note (renamed)`, `note (rewritten)`, `note` (gone), `check by hand` |

### `code-units.csv`: one row per referenced code unit

All passages that cite the unit, its status and the releases that changed it.

### `api-refs.csv`: one row per reference to an API endpoint

Covers API URLs (`dracor.org/api/…`, `staging.dracor.org/api/v1/dts/…`), Swagger deep links
(`dracor.org/doc/api#/public/<operationId>`) and endpoint paths in code spans (`` `/corpora/{corpusname}/play/…` ``).

| column | meaning |
|---|---|
| `kind` | `url`, `swagger deep link`, `api doc` (the documentation page itself), `code path` |
| `api_version` | `v0`, `v1`, `unversioned` (the redirect that will be shut down, #15) |
| `path` | API-relative path, version prefix and query removed |
| `old_template`, `old_operationId`, `old_spec` | matching path in the report-era specs (0.87.1, 1.0.0, 1.1.0, 1.4.1) |
| `target_template`, `target_operationId` | matching path and operation in 1.5.0-rc.1 `api.yaml`. Applied renames: `/play/` → `/plays/`, `cast` → `characters`, `metadata.csv` → `metadata/csv`. |
| `status` | `ok`, `path changed` (old v0 path pattern, new one in `target_template`), `legacy (v0 shutdown, #15)`, `operation exists` / `operation renamed` / `operation removed` (Swagger deep links), `served, not in api.yaml`, `endpoint removed`, `PoeCor API (not DraCor)`, `path pattern (elided)`, `no match in target`, `page` |
| `note` | e.g. that Swagger deep links break with Scalar (front end 3) and work on swagger.dracor.org (#14) |

### `summary.json`

Counts by report, kind, status and action.

## Findings (run of 2026-11-20)

**Code links:** 290 occurrences, 166 distinct links, 82 code units.

- **dracor-api** (176 occurrences, 62 units):
  - 8 units are unchanged since the report commit: `api:play-info`, `api:play-metrics`, `api:play-txt`, `api:corpus-meta-data`, the two CSV metadata endpoints, `config:resolve` and `wd:mixnmatch`.
  - 53 units have changed. 21 of them changed again in 1.5.0, apart from the prettier reformatting. These include:
    - `api:info` (activeLoads);
    - `api:corpora`, `dutil:get-play-info` and `dutil:get-plays-with-character`;
    - the corpus upload and creation path: `api:post-corpus`, `dutil:create-corpus`, `api:corpora-post-json`, `api:corpora-post-tei`;
    - `wd:get-author-info`;
    - the DTS citation tree, rewritten for DTS 1.0 (`local:generate-citationTree` → `local:citation-trees`; a candidate match, similarity 0.53).
  - Renamed (`cast` → `characters`, in 1.0.0): `api:cast-info`, `api:cast-info-csv`, `api:cast-info-csv-ext`, `dutil:cast-info`. Also `local:get-corpus-metrics` → `dutil:get-corpus-metrics`.
  - Gone: `local:id-to-url` (now through the shared identifier helpers).
  - After 1.5.0-rc.1, `main` differs in 4 units:
    - `api:corpora-post-tei` and `api:corpora-post-json` are merged into a single `api:corpora-post`, which dispatches on the Content-Type to `local:corpora-post-xml` and `local:corpora-post-json` (cf79cc5, "Accept admin requests without an Accept header");
    - `dutil:get-titles` and `dutil:filepaths` have changed.

    Rerun when 1.5.0 is final.
  - The branch link `43-refine-rdf-generation` (D7.1 fn. 86) no longer exists.
- **dracor-frontend** (97 occurrences, 19 units):
  - Every `.js` file of the report is now `.tsx`/`.ts` (35 file links can be repointed by file stem).
  - `fetch*` functions moved to `src/loaders.ts`, with low similarity.
  - `NetworkGraph`, `RelationsGraph`, `Sapogov` and `Yarkho` are rewritten (similarity 0.2–0.35).
  - `TrilckeFischer` is nearly unchanged (0.94–0.98).
  - `AuthorInfo` and `CorpusCard` now live in dracor-react.
  - `Home.js` and `Corpora.js` are removed. `fetchInfo`, `fetchData` and `edges` are gone.
- **dracor-metrics** (17 occurrences): `main.py` `metrics` changed in 1.4.0 (similarity 0.81).

**API references:** 252 occurrences.

- 105 are ok against 1.5.0-rc.1.
- 45 use the v0 path pattern (`/play/`, `cast`), and 35 use v0 or unversioned URLs that break with the v0 shutdown (#15).
- 39 Swagger deep links break with Scalar:
  - 33 operations still exist;
  - `get-cast` and `get-cast-csv` became `get-characters` and `get-characters-csv`;
  - `play-segments-xml` (`/segmentation`) was removed.
- `/rdf` is still served (`api:play-rdf`) but is no longer in `api.yaml`.
- The DTS URLs in D7.4 §3.4 point at staging, which now runs DTS 1.0 (1.5.0-rc.1). D7.4 used DTS 1-alpha.

## Caveats

- Unit detection is regex-based, not a parser. "renamed?" matches are candidates; check them.
- The similarity is token-based. A low value can mean a rewrite or just a moved helper.
- For the front end, the comparison across the JS → TS rewrite is rough. Use `target_url` as a starting point, not as a verdict.
